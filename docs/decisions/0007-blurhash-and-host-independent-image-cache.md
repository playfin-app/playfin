# 0007. BlurHash and Host-Independent Image Cache

Date: 2026-10-06
Status: Accepted

## Context

In Playfin, Jellyfin servers can be reached through several addresses (e.g. LAN `http://192.0.2.10:8096` and remote WAN `https://jellyfin.example.com`). Moreover, loading remote images over a WAN or mobile network can create noticeable latency and display flicker if placeholders are not shown immediately.

Requirements:
1. Images must load at the exact display size with an immediate BlurHash placeholder.
2. The image cache must survive an address switch (e.g. going from the local address to the WAN address): the cache key therefore must **not** depend on the host/IP/port.

## Decisions

1. **BlurHash decoding in the Rust core (`core/src/blurhash.rs`)**:
   - Native, optimised implementation of the BlurHash DCT decompression algorithm in Rust, without superfluous allocation.
   - Pre-computation of the cosine tables and direct decoding to 8-bit RGBA (`Vec<u8>`).
   - Fault tolerance: check of the Base83 table, of the lengths and of the factors. On a corrupted string, returns a typed `JellyfinError::Decode` error without ever panicking.
   - Exported through UniFFI as `decode_blurhash(blur_hash: &str, width: u32, height: u32) -> Result<Vec<u8>, JellyfinError>`.

2. **Extraction of the BlurHash metadata into `Movie` (`core/src/lib.rs`)**:
   - Resilient deserialisation of `ImageBlurHashes` (handling both the tagged Jellyfin structures `{"Primary": {"<tag>": "<hash>"}}` and direct strings).
   - Extraction of `PrimaryImageAspectRatio` to keep the native proportions of the posters without distortion.

3. **Host-independent cache key (`ImageCache.swift`)**:
   - Normalised key: `"<itemId>_<kind>_<maxHeight>_<maxWidth>"`.
   - The full URL is never used as a storage key. So whether the image is downloaded over the LAN or the WAN, the key on disk and in memory stays strictly identical.
   - Two-level cache:
     - Memory: `NSCache<NSString, NSImage>` with a cost limit and an item-count limit.
     - Disk: `~/Library/Caches/com.playfin.app/images/`.

4. **`AsyncArtwork` SwiftUI component (`AsyncArtwork.swift`)**:
   - Instantly shows the `BlurHash` placeholder generated by the Rust core (or an elegant fallback).
   - Loads the image in the background: Memory -> Disk -> Network.
   - Cancels the network task if the cell leaves the screen (`.onDisappear { task?.cancel() }`), ensuring perfect smoothness at 60/120 Hz while scrolling.
   - Soft fade-in transition when the real image is decoded.

## Consequences

- **Smoothness and visual performance**: No empty or grey display while navigating; posters and banners appear instantly as elegant blurred gradients before the high-resolution render.
- **Bandwidth saving**: Zero re-download when the network address changes.
- **Memory stability**: Strict limit of the memory footprint through `NSCache` and removal of useless network requests during fast scrolling.
